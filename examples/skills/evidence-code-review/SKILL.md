# 基于证据的代码审查

1. 从真实任务和已批准计划理解变更边界。
2. 按需读取 `references/checklist.md`。读取实际修改和有关调用方，不凭摘要猜测代码内容。
3. 将发现分为确定缺陷、需要验证的风险、设计建议。每项附路径、相关行为和可复现条件。
4. 检查测试是否实际运行、对应哪个版本、退出状态是什么；没有执行记录则写未验证。
5. 对依赖用户偏好的设计点使用 `request_decision`，不要默选。
6. 提交结构化结论、未解决问题与证据；只有真实验收条件满足才建议接受。

审查阶段不写代码、不运行超出本阶段白名单的工具；Skill不改变这些权限。
