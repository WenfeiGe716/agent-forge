# 需求澄清与定向协作

## 适用场景
读取定向需求后，识别会影响代码行为的未确认事项。不要为表演协作而强制提问。

## 操作
1. 先核对用户需求、已确认决定和项目规范。只读取授权范围的必要文件。
2. 按需读取 `references/checklist.md`，区分已知事实、推测、必须由用户决定的事项。
3. 必须决策时调用 `request_decision`，给出清晰问题、影响、可选方案，允许补充说明；本次仅调用这一工具，等待真实回答。
4. 从本次授权协作池挑选必要成员，形成议程。遵守成员通信范围，不私自加入其他Agent。
5. 依据实际协作结论输出行动项：负责人、具体任务、输入依赖、验收条件和未解决问题。
6. 目标和证据满足才提交候选结果；发言次数不是成功依据。不要以读取文件代替运行测试。

## 安全边界
本Skill不赋予额外工具、文件、网络权限。已批准计划的范围发生变化时，需要用户重新确认，不能用补充聊天绕过审批。
