# Agent Forge v0.7.0 — 定向协作链与版本化Skill

日期：2026-09-09。基于v0.6生产源码继续实现。面向团队内部、本地部署、通用软件开发。

## 1. 交付结论

已实现并联调：定向需求 → 按需请求用户决策 → 按实际会话组织多人协作 → 有责任人与验收要求的行动项 → 任务看板、成员会话和事件追溯。新增Skill库、审核与版本、逐Agent绑定，以及真正进入执行上下文的加载工具。

这是一份经过核心流程验证的工程版本，不是生产成熟度认证。实际联调使用SQLite、本地持久化编排器、真实HTTP双协议脚本服务、真实Git与固定可信单元测试。模型回复是明确标记的脚本化服务，不能证明真实LLM的规划、理解Skill或代码开发质量。没有把测试夹具作为真实代码沙箱交付。

## 2. 用户从哪里操作

### 定向下达与继续输入

办公室底部可选择收件人，并区分“新建定向需求”与“给当前任务补充说明”。任务表单默认启用协作链，可明确选择入口成员。支持精确 `@Atlas`、`@成员ID` 和 `@{部门名称}`。部门有多个普通成员且没有唯一负责人时，必须显式选择入口；不按数据库顺序猜测。

开发模式入口须为该运行负责人；纯讨论可以使用授权子团队中的任意成员。创建两成员讨论模板时，表单会自动把入口调整为子团队中的成员，不错误保留全局负责人。协作候选池、入口成员及版本化配置写入快照。

追加说明有明确收件人和幂等键，持久化后进入所选成员的后续模型请求。不重新启动已经完成的步骤，不增加工具权限，也不是重新批准扩大后的需求。已完成、取消、异常待处置及等待成果验收的运行拒绝追加说明。

### 主动提问、人工决策与恢复

新增 `request_decision` 工具：问题、背景、选项、自由文本开关形成不可变摘要。不是每项任务强制问问题，Agent应只在缺少必要信息时请求。

提出问题的步骤进入 `waiting_decision`；同一批其他可运行步骤可以继续。没有可运行步骤时，运行显示等待决策。等待不消耗模型调用预算，也不计为自动执行耗时。回答者需要项目访问权和写权限。

回答绑定问题摘要，相同回答幂等，冲突回答或错误摘要拒绝。答案和追加说明进入原步骤后续上下文，并记录实际送达回执。拒绝继续会保留已有内容并转人工，不默认选择一个答案。取消或中断会关闭尚未回答的问题，保留问题原文，不假装已经回答。

实际进程停止/重启、暂停后回答、继续、取消和迟到回答均做了真实HTTP验证。结果未知的在途外部调用仍遵循原有保护：不会因为本功能而盲目重做。

### 多人会议与通信范围

入口成员在读取需求/答案后，提交议程、摘要和参与名单，系统只允许召集授权协作池内的成员。新增真实Meeting实体，关联运行、主持人、参与者、议程、执行中的发言步骤、目标复核、结束结果和行动项。

成员配置新增部门字段和通信范围：运行内、同部门、汇报链、指定成员。发送消息、委派、依赖交接及共享会议上下文均在服务端校验；共同参加会议要求成员间的通信许可。组织关系和Skill都不能自行扩大权限。部门字段不等于完整的部门/职位资源管理器。

会议保持目标与证据收敛，不按固定讨论轮数停止。每次复核的缺项会传给后续协作。目标达到提交要求才结束会议；停滞、预算、拒绝或中断与成功分开。

### 3D会议

办公室直接读取 `/api/office/state` 的真实会议。指定成员绕静态家具走向会议席位，坐下参与；实际执行中的成员对应发言/复核动作，其他成员聆听。等待用户回答或暂停保留席位，不播放虚构发言。只有收到结束/取消等状态才离开，超过旧6秒或60秒也不会自行散会。

只有一个实体会议区，共6席，按确定性先到租约分配。超出6席以及另一并发会议的成员显示远程参与，避免重叠座位。断线/快照过期进入安全等待。行走、入座和返回都不阻塞后台通信、模型调用或开发任务。

v0.4–v0.6的工位坐姿、领导来访起身、空闲抢占、城市交通保留。普通两人消息来访仍是有限的事件演绎；本轮新增的持久会话生命周期用于多人会议，没有将所有直接消息变成即时聊天协议。程序化人物、静态家具避让及受限静态GLB能力也保持原边界。

### 行动项与追溯

开发流程由实际计划生成行动项，关联会议、用户决定、计划摘要、责任人和执行任务。计划未批准显示待批准，任务交付后显示待验收，最终人工接受才显示已验收。不能把卡片拖成完成来绕过验收。

纯讨论可增加一个真实模型执行步骤来整理建议行动项。它们明确显示“建议行动项 · 未执行”，不会自动改代码；本轮没有“纯讨论建议一键转任意后续DAG”的通用调度器。

协作工作台包含决策中心、会议与决议、责任人×行动项、成员会话和追溯时间线。行动项可打开其执行会话；看板卡片可返回同一运行的协作链。会话支持按成员/关键词检索和分页，展示实际公开回复、工具调用及回答回执，不返回系统提示或供应商原生隐藏思考块。事件采用服务端游标分页，城市和空闲事件不混入业务时间线。

## 3. Skill：从配置到实际调用

### 能力包与管理

使用 `SKILL.md` + 可选 `references/`、`assets/`、`scripts/` 文本资源结构。支持界面新建/编辑、ZIP导入与导出、历史版本、批准/撤销及整个Skill启停。库在本组织共享，请勿放入密钥或不应向其他团队账号公开的资料。

`name`、`description` 为必要元数据，支持简单标量、块文本与一层字符串metadata。实现是有界YAML子集，不宣称任意第三方Skill包可以原样运行。YAML标签/别名、复杂嵌套、二进制资产、路径穿越、符号链接、重复路径、加密ZIP和超限内容拒绝。

每包最多80个文件、合计1.5MB、单文件200KB；接受UTF-8文本和限定扩展名。修改创建不可变新版本，默认待审核；审核绑定内容摘要。运行快照冻结Agent所绑定的明确版本，之后编辑不污染在途任务。撤销或停用仍会在后续调用前检查，不能撤回已经发给供应商的请求。

### 逐Agent绑定

成员配置可绑定多个Skill（本版每位最多12项），逐项配置版本、按需/阶段加载、JSON参数及包内脚本开关。不同Agent可以绑定不同版本、不同参数，继续使用各自供应商和模型。

按需模式在初始上下文提供名称、描述与版本目录；模型调用 `activate_skill` 后读取正文，使用 `read_skill_resource` 取资源。阶段加载模式在阶段开始时提供正文。加载、资源读取、版本、摘要及执行记录关联实际运行和成员；不是只在界面保存一个Skill名称。

包的 `allowed-tools` 字段只是元数据，绝不自动扩权。Skill属于受控操作说明，不能替代系统策略、项目访问控制或计划审批。

### 脚本执行边界

只有管理员在Agent绑定上明确启用脚本、当前任务为开发阶段、原有角色具有命令权限时，才开放 `run_skill_script`。它通过既有沙箱broker执行单文件Python、JavaScript或Shell脚本，不调用宿主机subprocess，不自动安装依赖。工具链需要已存在于项目执行镜像。

本版把脚本文本传给对应解释器执行，支持参数安全引用；不是将完整Skill目录作为可执行文件系统挂载。因此依赖相邻模块、相对文件、二进制资产或额外包的第三方脚本需要改造或后续执行后端支持。模型也不能靠“先声明一个Skill”获得MCP访问权。

本轮测试验证了权限拒绝和转发到既有沙箱接口；真实Docker/gVisor执行没有在本环境验收。默认三个起步Skill没有脚本。

### 随包三份起步Skill

`examples/skills/requirements-clarification.zip`：需求澄清和人工决定。

`examples/skills/evidence-code-review.zip`：根据实际证据进行代码审查。

`examples/skills/regression-test-design.zip`：边界与回归测试设计。

三份均由本项目编写，已通过本版实际导入解析校验。逐个导入、检查、批准后再绑定，不自动注入正式平台。

格式与渐进加载参考（读取日期2026-09-09）：
- https://agentskills.io/specification
- https://agentskills.io/client-implementation/adding-skills-support

### 实际链路证据

HTTP主流程发生24次实际模型HTTP请求：按需加载Skill及资源 → 主动提问 → 用户选择并追加说明 → 原步骤继续 → 目标会议 → 行动项/计划 → 人工批准 → 实际Git修改 → 三项固定可信unittest → 审查 → 人工验收。加载为一次activate和一次资源读取。答案进入多个后续任务的实际模型上下文；不是每次送达都重新提问。

证据：`chain-run.json`、`chain-events.json`、`chain-collaboration.json`、`chain-changes.patch`、`chain-report.json`、`chain-source.zip`。原始导入目录未修改。模型回复为脚本化HTTP服务，不是真实LLM。

浏览器链路另外实际创建Skill、审核、绑定成员、选收件人、提交需求、回答、观察至少三名会议参与者入座、查看行动项/会话/Skill事件，再通过真实计划批准和人工验收。关键画面来自真实DOM/WebGL渲染，非设计效果图。为了检查入座，验证服务中的一个脚本化讨论响应有明确的24秒延迟；这不属于生产逻辑，也不作为性能证据。

重启专项实际停止并重启独立API和夹具进程，复用同一数据库与加密密钥；问题ID、摘要及模型调用数保持不变。暂停时回答仅保存，恢复后才继续。取消中的未答问题关闭，迟到回答返回409。没有宣称覆盖任意掉电位置、磁盘故障或所有外部副作用。

### 测试方法与修正

Chromium使用ANGLE/SwiftShader软件GPU。当前容器管理策略禁止URL导航，没有修改或禁用该策略。使用 `page.set_content` 加载最终单文件产物；正式页面由受限桥接将真实HTTP/SSE传给本地服务。覆盖实际DOM/WebGL/API及持久化，但不覆盖目标机器普通地址栏导航、Cookie/HTTPS部署、原生EventSource自动恢复或原生下载管理器。ZIP等产物以实际HTTP内容另行验证。

本轮修正了浅色卡片继承暗色主题文本导致的对比度问题、纯讨论模板入口默认成员错误、会话切换中旧响应覆盖新选择和历史分页被轮询重置。测试脚本修正了附带成员数量的可访问按钮名、实际批准按钮文字、等待Skill异步列表加载后再操作，以及重启时端口TIME_WAIT的探测方式；没有通过删除失败用例替代修复。

## 5. 明确未完成的范围

- 真实供应商/真实LLM的自主提问、Skill选择、目标判断、复杂工程开发质量与多Agent收益基准。
- Docker/gVisor实际隔离、Skill脚本在真实容器中的验证；Temporal/PostgreSQL整栈。新增活动和信号已注册，不能以本地模式结果代替这些运行器的验证。
- 任意嵌套流程、多阶段动态增删参与者、完整部门/职位/工位管理、外部Agent访客连接、通用MCP插件管理。
- 全量第三方Skill运行兼容性、任意YAML、二进制资源、完整目录式脚本运行或自动依赖安装。
- 正常部署的原生浏览器链路、硬件GPU流畅度、完整tsc语义检查、长时间/压力测试、数据库升级回滚、备份恢复、HA和供应链审计。
- 既有`needs_attention`运行保持保守占用；本轮没有新增“核验未知外部结果后关闭异常运行”的完整向导。

## 6. 复验与部署

正式入口与离线安装参见根目录README。完整离线包仍针对Linux x86_64 / CPython3.13及兼容系统库，沿用此前27个从已安装发行包重新打包的wheel，保留许可证、来源及哈希，不是上游新下载的原始wheel。没有修改DNS或TLS/网络管理策略。

```bash
bash scripts/install-offline.sh
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
node tests/visual/meetings.test.mjs
node tests/visual/behavior.test.mjs
node tests/visual/etiquette.test.mjs
node tests/visual/city.test.mjs
.venv/bin/python scripts/start-local.py
```

测试环境复验使用独立目录：

```bash
FORGE_E2E_STATE=/tmp/forge-v07-check .venv/bin/python tests/e2e/start_fixture.py --seed
# 另一个终端，同一个FORGE_E2E_STATE：
FORGE_E2E_STATE=/tmp/forge-v07-check .venv/bin/python tests/e2e/v07_http_acceptance.py
```

浏览器脚本需Playwright、Chromium和可用图形环境，它们不包含在离线包内。`v07_live_acceptance.py`建议使用另一份新验证目录，避免其他异常运行的全局占用影响会议画面；`v07_preview_acceptance.py`不访问后台。重启脚本只允许控制明确指定的`start_fixture.py`子进程。

升级前处理完在途任务，停止旧服务，备份数据库、工作副本和加密密钥，在独立目录验证。新增表会建立，但没有完整数据库迁移/回滚管理器；不支持跨版本在途工作流热替换，也不得让两个编排器管理同一数据目录。
