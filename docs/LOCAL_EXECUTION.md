# 本机执行与三档权限

新项目默认 `execution_mode=local`、`permission_profile=ask`。已有项目和运行快照缺少执行模式时按原来的 `container` 处理，普通配置编辑不会静默开启宿主机执行。

| 界面选项 | 项目内命令 | 联网与越界 | 生效范围 |
| --- | --- | --- | --- |
| 请求审批 | 在原生系统沙箱约束内执行 | 固定命令、明确路径、联网开关形成一次性申请，由管理员确认摘要 | 当前运行与任务 |
| 帮我批准 | 与请求审批相同 | 独立审批 Agent 无工具地判断；高风险、不明确、模型不可用或预算不足转人工 | 当前申请，不产生永久授权 |
| 完全访问 | 显式移除原生文件和网络沙箱 | 使用当前系统账号可访问的文件和网络；必须勾选风险确认，不可由 Agent 切换 | 新运行冻结的项目配置 |

完全访问不是角色权限提升：没有命令工具授权的成员仍不能调用命令工具。三档权限也不跳过团队发布、应用、开发计划审批和最终成果验收。

## 本机与容器

本机受限执行目前实现 macOS Seatbelt；不支持的系统或缺少系统隔离能力时明确显示未就绪，不自动取消限制。新建项目可以另选 Docker/gVisor 容器，容器保持断网和原有资源约束。

本地启动入口：`bash start.sh`。默认不配置、构建或重启 Docker。仅显式传入 `--with-container-broker` 才尝试准备可选容器服务。本机执行开关只由本地启动器在监听回环地址时开启；网络部署不会默认取得宿主机执行权。

每位执行成员使用独立的本机任务工作副本：`DATA_ROOT/runs/<run_id>/tasks/<task_key>`。结果通过原有冲突检查集成到同一运行的 `integration` 目录，并生成可验收成果。这里的“本机执行”指命令和文件实际落在本机，不代表自动覆盖最初导入的源目录；原始导入目录保持不变。

原生命令有超时、输出大小和单文件大小限制；不把配置中的容器 CPU 核数与内存额度宣称为本机硬额度。需要此类资源隔离时选择容器。命令环境不直接继承平台的模型密钥、Cookie、代理变量或用户 shell 启动文件。完全访问仍可能通过当前账号的文件权限读取本机数据，不能仅依靠环境变量清理保护秘密。

## 审批与证据

- 权限申请包含完整命令、理由、联网开关、精确额外文件路径及读写方式；不接受把整个主目录隐式授权为一个文件。
- 审批绑定运行、任务、成员与摘要；命令或权限变动必须重新申请。普通会话回答不等于执行授权。
- “帮我批准”使用冻结团队中的独立审查成员模型；申请成员不能自行审批。模型审查计入调用预算，不重试结果不明的请求。
- 原生命令记录实际工作目录、执行模式、权限档、退出码、输出、超时和执行 ID。未知结果不自动重放。
- 成员消息必须进入接收者的后续模型上下文；动画本身不构成通信或执行成功的证据。
- 工具安装既可使用已登记、固定版本的离线工具审批，也可通过精确执行权限申请处理联网安装。不是所有安装都会自动获批。
- `inspect_environment` 接受 Agent 根据实际项目选择的命令名称，在本次本机/容器和项目依赖目录中定位，返回真实路径和缺失状态；工具名不是平台写死的应用白名单。发现结果不等于已验证版本或兼容性。
- “请求审批”和“帮我批准”的临时越界/联网命令禁止派生子进程，以确保一次性授权不会留在后台。需要子进程的命令会失败关闭，不自动切换完全访问；审批前会显示此约束。
- 常规项目内命令清理继承的进程组，不是面向恶意常驻程序的整机进程监管。多成员文件操作使用逐级不跟随符号链接的文件描述符，避免路径检查与访问之间被切换。更强的进程/资源隔离仍使用容器模式。

## 验证

`scripts/verify-native-team-live.py` 是可选的真实模型验证工具，会创建独立的公开示例项目和验证成员，可能产生模型费用，不修改既有成员绑定。计划和安装审批是分开的显式命令，脚本不自动批准模型生成的计划或未知工具。

静态就绪检查不会发起模型推理。只有实际运行产生的文件、命令回执和消息纳入事件，才构成真实执行证据。
