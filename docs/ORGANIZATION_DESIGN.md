# 楼层、部门、团队与办公区域

组织关系是一个楼层承载一个部门，部门包含多个办公团队，团队包含多个实际 Agent。不同团队的员工名单和桌位独立，同一成员在一份布局中只能占一个团队的一张桌。

## 默认开发办公室

一楼为研发部，内置开发团队。初始布局包括代码规划与架构、开发工位、测试质量、需求分析、协作会议室、休息区、卫生间和饮水间。错落的工作区、会议室玻璃隔断、沙发茶几、饮水设施和绿植由配置位置生成，不是固定贴图。

初始模板提供 12 张桌和 4 名编制，只安排现有且可唯一识别的 Atlas、Nova、Echo、Sage。缺少成员时保持空桌，不创建替代成员，不修改岗位、模型、Skill 或工具权限。需求分析区域可以暂时空置。

只在没有组织设计历史时初始化默认模板。此前未经人工修改的内置初始模板可追加升级版本；一旦存在人工草稿、应用记录或成员空间改动，系统不会自动重排。旧版本及旧任务快照保留。

## 编辑与应用

进入「设计中心 → 办公室 → 查看 / 编辑 → 编辑并创建新版本」。

1. 管理楼层名称与所属部门；新增楼层不会复制其他层的团队或员工。
2. 选择功能区，在平面图中拖动位置、拖动右下角缩放，或输入精确坐标。移动业务区时，其桌椅和成员位置一起移动。
3. 每个团队选择独立业务区；需要新团队时可添加业务区，或拆分没有桌位的业务区。
4. 分别设置办公桌数量、员工编制、实际员工，满足「实际人数 ≤ 编制 ≤ 桌数」。扩容只增加空桌；跨团队调入会腾空原桌，不复制成员。
5. 保存草稿、审核发布、明确应用。设计中的修改不会自动改变工作台；已开始的任务继续使用冻结版本。

标准新布局的每个楼层必须有会议室、卫生间和饮水间。最后一个必需配套不能被删除或改成其他类型，但位置、名称、颜色和尺寸可编辑；允许增加同类配套。休息区及其他业务区按需调整。会议室至少 4 × 3，其他专用公共配套至少 3 × 3，区域不能重叠或越界，桌椅完整占地必须在业务区内。

历史规则布局保持兼容，不会被读取或展示操作自动升级；新建标准布局使用完整公共配套规则。`layout_version` 是布局规则版本，区别于资产的草稿 / 发布版本。

## 工作台

按楼层切换 3D 办公室；成员面板可按部门楼层及团队筛选。空桌只显示家具，不显示虚构员工；未安排工位的成员显示「工位待安排」。区域标签提供完整团队容量提示，成员真实任务占用仍按全局状态判断。

空间分组不是执行权限：坐进开发区不等于可执行代码，配置成员也不等于模型调用已成功。执行就绪与真实运行证据另见[本机执行说明](LOCAL_EXECUTION.md)。
