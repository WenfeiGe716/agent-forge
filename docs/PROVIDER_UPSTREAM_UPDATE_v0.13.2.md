# v0.13.2：按供应商从上游拉取并全量更新替换

## 使用

进入“供应商与模型”，选择任意已创建的供应商。所有连接使用相同流程，不按智蔻或其他供应商名称特殊处理：

1. 点击“全量更新替换”，立即使用该连接的地址、凭据和协议重新请求上游目录。
2. 查看当前上游数量、拉取地址与时间、新增/移出/恢复配置数，以及移出配置关联的 Agent 主模型和备用绑定数。
3. 核对清单并勾选确认，再提交替换。切换供应商会清除待确认状态。

“从上游拉取更新”仅更新候选目录，不修改模型配置；“全量更新替换”才会经确认调整当前配置列表。选取少量型号时仍可使用“导入所选为停用配置”。页面全局刷新只读取状态，不代表重新拉取上游。

## 全量替换的边界

- 当前型号集合以选中供应商本次完整返回的模型 ID 为准；其他供应商不受影响。相同模型 ID 属于不同供应商时仍是独立配置。
- 新型号创建为停用配置。不自动推断工具调用能力、价格或请求参数，也不自动绑定 Agent、发起 Benchmark 或推理。
- 上游仍有的型号刷新目录元数据，但保留管理员编辑的名称、参数、价格、能力评分及既有启停状态。同一型号已有多份参数配置时保留它们，不合并或丢失人工配置。
- 上游不再有的型号从当前列表移出并停用。保留模型 ID、历史版本、评分和既有运行快照；“已移出 / 目录未找到”筛选可以查看。历史模型不能绕过目录恢复直接启用。
- 上游重新出现的型号可确认恢复原配置，不重复创建，也不自动重新启用。
- Agent 主模型和备用绑定不自动改写。若绑定的模型被移出，管理员需为后续任务选择可用配置；已有任务的冻结快照不被改写。

这不是永久删除或无条件覆盖人工治理结果，而是替换该供应商的当前可配置型号集合。

## 拉取范围与失败保护

通用管理层支持当前全部适配器：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Gemini 和自定义 JSON/HTTP。DeepSeek 等兼容连接使用其自己的 OpenAI 兼容地址与凭据；平台不将官方公开型号表冒充该账户实际可用目录。

自定义 JSON/HTTP 连接需配置 `discovery` 的目录接口与字段映射；仅支持 GET JSON 目录。未配置、返回错误、不完整分页或无法验证的目录会提示失败，不能用于全量替换。任意私有分页规范并不会自动被猜测实现；不支持的分页需要先扩展适配器或使用返回完整列表的目录接口。

标准适配器按其已实现的协议分页读取，最多 10 页、2000 个模型，单响应最多 8 MB。达到保护边界、游标重复、分页标志与游标矛盾、鉴权失败或请求失败时拒绝将部分结果作为成功目录。显式拉取使用 no-cache 请求头；平台仍只能获取上游向当前凭据暴露的数据，不能绕过账户权限或强制上游展示隐藏型号。

失败保留最后成功的目录和配置。空目录可以被显示，但禁止用空目录执行全量替换，避免异常清空。替换要求 5 分钟内的成功拉取、精确的连接修订与目录摘要，以及显式人工确认；连接或目录在确认期间变化时拒绝旧确认。

## 数据与审计

目录继续按 `provider_id + revision_id` 隔离。新增拉取回执表和可恢复的模型移出状态表，通过启动时建表升级，不重写或删除原有配置表。

每次拉取记录新增、信息更新、上游移出、重新出现、未变化的型号 ID 清单。替换和导入记录操作者、供应商、修订、目录摘要及受影响的配置 ID。普通模型编辑与目录替换使用供应商级写锁，避免并发编辑重新启用已移出的模型。

## 验证命令

```bash
PYTHONPATH=backend .venv/bin/pytest backend/tests -q
node --test tests/frontend/*.test.cjs
node scripts/build-offline.mjs
node scripts/check-source.mjs
```

前端构建和检查为离线转译与语法验证，不宣称完整 TypeScript 语义检查。协议测试使用隔离 HTTP 替身；真实供应商账户的目录以实际拉取结果为准，不以测试替身证明所有官方账户可用。

只读核对 OpenAI 兼容网关目录（不打印密钥、不调用推理）：

```bash
.venv/bin/python scripts/verify-provider-catalog.py --provider-url https://api.gaoxin.net.cn/v1
```

追加 `--pull` 会显式刷新候选目录，但不会导入或替换配置。该差分脚本仅用于无分页的 OpenAI 兼容目录诊断；通用产品功能不依赖此脚本或该供应商地址。
