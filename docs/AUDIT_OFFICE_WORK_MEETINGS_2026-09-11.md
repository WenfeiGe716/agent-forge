# 3D 工作动作与会议场地审计

日期：2026-09-11。范围：检查真实任务事件、办公室投影、人物动作、会议占用与并行任务关系。只读检查与隔离内存模拟；未调用生产模型、未创建任务、未修改数据库或审批数据。本报告中的待补能力没有在 v0.15.9 中实现。

后续状态：v0.16.0 已实现单人成员独立执行、负责人按需召集讨论和成员直接求助；下文关于固定需求协作流程的描述是 v0.15.9 审计时状态。手部击键、短动作反馈、多会议室和休息区场地回退仍未在本次实现。见 [团队自治验证](VALIDATION_TEAM_AUTONOMY_v0.16.0.md)。

## 已有行为与缺口

| 问题 | 当前实际行为 | 缺口 |
| --- | --- | --- |
| 工作时敲键盘 | `writing` 映射到 `typing`，默认人物双手随时间上下摆动 | 手指没有独立击键，默认工位手部与键盘位置仍不贴合 |
| 执行状态变化 | 有思考、阅读、写入、命令执行、审查、通信、等待审批与需人工处理等状态 | 工具完成立即覆盖写入状态；约 1.2 秒的轮询可能完全漏过短写入动作；部分真实执行工具未映射 |
| 何时进会议室 | 后端存在真实会议记录，且成员属于该运行时，呈现进场、听取或发言、散会回工位 | 新需求协作流程尚未提供“单人直接处理、按需才讨论”的完整分支 |
| 会议室占用 | 本层一个会议租约，最多六个实体席位；并发会议、超员或路径不可达时在工位远程参会 | 多个会议室未独立调度；休息区没有讨论回退机制 |
| 并行任务与成员交互 | 运行隔离、全局占用统计、按优先级显示一个当前状态；真实消息按运行传递 | 一个 3D 人物不能同时表现多个任务；走路、气泡或固定时长交谈不代表消息已被理解或任务已完成 |
| 自定义人物 | 导入 GLB 有渲染路径 | 当前静态渲染路径没有默认人物的程序化关节动作 |

### 动作链

- `backend/forge/office.py:16`：工具到工作状态的映射。
- `backend/forge/office.py:124`：`tool.completed` 将当前阶段设为 `thinking`。
- `frontend/src/office/useOfficeFeed.ts:15`：轮询间隔为 1200ms。
- `frontend/src/office/behavior.ts:24`：`writing → typing`。
- `frontend/src/graphics/characters.ts:104`：打字双手上下摆动，振幅 0.014 世界单位。
- `frontend/src/graphics/furniture.ts:61` 与 `frontend/src/graphics/officeWorld.ts:36`：键盘与默认工位位置。

隔离复现：单个状态包含写文件开始及完成事件，但最新 presence 为 thinking 时，人物不会播放 typing。默认工位确定性几何检查中，手指与最近键帽的水平间距约为 0.231 世界单位，因此不能把现状描述为手指已实际触键。`run_approved_command`、`run_installed_tool` 等工具和项目 `check` 验收尚未全部投影到执行动作。

### 会议链

- `backend/forge/workflow_core.py:152`：协作流程需求接收后，有参会图即开启会议。
- `backend/forge/schema.py:197`：`IntakeResult.participants` 最少两人。
- `backend/forge/engagement.py:28`：会议要求至少两位不同的已授权运行成员，校验通信范围。
- `frontend/src/office/meetings.ts:20`：本层单个场地租约。
- `frontend/src/office/meetings.ts:37`：占用、超员或路径不可达回退为工位远程参与。
- `frontend/src/graphics/departmentOffice.ts:108`：只收集第一个会议室的六个实体席位。

单人会议当前被拒绝，不等于单 Agent 能自动跳过讨论直接执行。多人的跨楼层会议也可能只有一名本层成员进入本层会议室；场地分配没有“至少两名本层实际参会者”的条件。动画行走与落座不阻塞后端执行，会议也不会因动画播完而自行结束。

## 建议下一轮实现的规则（尚未实施）

1. 单人可独立完成的任务直接工作；两人及以上在需求澄清、方案分歧、交接或联合复核需要同步讨论时才召开会议。
2. 按运行与参会成员分配场地：可用会议室 → 同层可用且容量合适的休息区 → 工位远程参与。场地需独立预约、容量检查，并与空闲休息动作共用占用信息，防止重叠抢座。
3. 只有一个本层实际参会成员时，在工位远程参加跨层会议，无需独占会议室。
4. 工作动作从真实事件驱动；短事件可以呈现短暂的“刚完成”反馈，不伪造仍在执行。审批、暂停、失败、任务切换和断线应及时覆盖旧动作。
5. 校准工位、坐姿与手部目标；对自定义 GLB 明确区分有动画骨骼和静态模型，不宣称所有模型均可敲键盘。

## 验证记录与限制

通过子代理对当前 TypeScript 源码做隔离内存模拟：行为 35/35、会议 13/13、来访接待 22/22，共 70/70，退出码 0。测试脚本的证据文件写入被截获，没有向生产目录输出文件。另做手部位移、键盘间距、短写入状态的确定性检查。

这些测试证明已存在的行为及缺口，并不证明建议规则已经实现；本轮未发起真实任务或模型调用。
