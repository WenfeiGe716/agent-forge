# 安全边界与未完事项

本版本是受信任团队内的工程Alpha，不是安全认证、隔离证明或生产可用性承诺。不要第一天就接入生产凭据、敏感客户数据或不可恢复的外部操作。

## 已写入代码的控制

浏览器侧使用HttpOnly、SameSite会话Cookie；写请求要求同源标识与Origin检查；账号停用、项目成员范围和只读身份由服务端校验。密码使用scrypt，登录令牌只存摘要；供应商凭据由Fernet加密并保留版本引用。生产网络需自行配置TLS。

模型只得到授权工具，不能访问Docker API令牌或供应商密钥。工具读写拒绝目录穿越、符号链接、硬链接和特殊文件。默认屏蔽常见秘密文件名。原始导入目录只读；执行工作副本不带原仓库钩子/历史/凭据。

只有sandbox-broker拥有宿主机Docker socket。代码容器不挂载Docker socket，默认runsc、无网络、只读系统文件、移除capabilities、限制进程/CPU/内存/单文件大小，工作区之外不挂载业务数据，.git嵌套只读。镜像由管理员预构建并加入白名单；不会自动拉任意镜像或直接在宿主机执行模型生成的shell。

## 不应误解的边界

**Docker socket控制者接近主机管理员权限。** broker自身需要作为高信任组件保护，它不是可以对不可信租户开放的公网服务。数据库/编排器/broker默认不发布主机端口，但网络配置错误可能破坏这个假设。

没有穷尽所有文件竞争条件或完成攻击面审计；路径检查、文件名过滤、gVisor均不是完整安全证明。内网模型地址检查不固定DNS解析结果，不能视为完整的DNS重绑定/出网防护；重要环境应使用网络白名单与受控DNS。普通源码中的密码可能不被文件名规则发现，提示注入也无法靠角色提示词彻底解决。

代码沙箱限制单文件大小和内存，但**没有整个工作区磁盘/文件数的操作系统硬配额**；恶意或异常构建仍可能耗尽主机存储。当前最大导入200MB/30000文件不能代替执行期磁盘配额。大仓库需要优化批量Git操作与文件扫描。

命令输出和上下文有长度上限；不会静默截断模型上下文后继续伪装完整理解。原始供应商错误响应不进日志，避免回显密钥；应用/基础设施日志仍应按敏感信息处理。Anthropic协议块为保持会话有效保存在内部任务上下文中，不把它们作为可公开的模型推理过程呈现。

暂停/取消在安全边界应用，不能撤销已经发出的模型请求，或强制撤销已完成的副作用。本版没有生产推送、部署工具和远程Git凭据；人工应用补丁也需要独立审阅。

## 与完整成熟版的差距

| 领域 | v0.1边界 / 后续必做 |
|---|---|
| 真实集成 | 尚未在目标机器完成Temporal、PostgreSQL、runsc、真实模型及浏览器联调 |
| 前端 | TS/TSX语法通过；npm正式构建、完整类型检查、视觉/交互/可访问性验收未完成 |
| 供应商 | 两种协议；复杂鉴权、协议扩展、型号能力、推理参数与故障切换需要真实兼容测试 |
| 执行环境 | Linux容器；没有原生Windows/macOS/GPU/GUI执行后端、服务预览和项目多容器编排 |
| Git工作流 | 当前文件快照和成果导出；无原仓库历史保留、远程拉取/推送、自动PR、连续项目基线更新界面 |
| 人工接管 | 计划/成果审批、暂停/继续/取消、新运行；无在线编辑计划/文件、人工冲突解决器和恢复现场编辑器 |
| 可靠性 | 保守地把未知结果转人工；未验证整机故障、数据库恢复、活动超时和长时间压测 |
| 治理 | 没有金额/Token硬预算、租户配额、供应商限流、令牌轮换、自动清理和分级数据保留 |
| 身份 | 内部账号；无SSO/MFA、邀请流程、密码自助恢复和完整账号生命周期 |
| 工程化 | 无正式迁移版本、完整依赖锁、镜像digest、软件物料清单和漏洞扫描报告 |
| 生产运维 | 单机、停机备份脚本；无HA、在线备份、恢复演练、指标告警或服务级别承诺 |
| 业务质量 | 测试桩验证代码路径，不代表真实模型任务成功率；30任务×3次基准尚未执行 |

生产化前应先在隔离测试主机走通样例，再做真实仓库回归、安全测试、故障注入和成本评测，不以3D页面看起来完整作为成熟标准。
