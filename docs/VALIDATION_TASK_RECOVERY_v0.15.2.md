# v0.15.2 · 任务停止说明与办公团队选择

## 复现与原因

2026-09-10，在桌面工作空间的私有只读数据库副本上检查历史运行：状态 `needs_attention`，3 次模型调用，唯一执行阶段为 `plan`。原始错误是 `12 validation errors for Plan`，缺少 `key`、`agent_id`、`acceptance` 等字段。诊断阶段未修改历史运行、快照或生产配置，也未向供应商发起推理。

`node --test tests/frontend/run-recovery.test.cjs` 先在真实 CollaborationPage 组件上复现：协作页不显示错误原因或重新发起入口，却显示终止运行不能接受的补充指令表单。修复后，同一回归要求看到计划格式说明、折叠技术详情和显式确认入口。

## 修改

- 停止原因独立于“待审批”。协作页及任务详情显示原因、阶段、相关成员、下一步操作；看板和办公室提供查看处理入口。无法分类的错误保守展示，不臆测成功或保证重试可恢复。
- 重新发起只打开确认表单，保留需求、项目、明确成员范围、协作方式和设计来源，不复制凭据、历史模型配置、批准结果或工具命令。模板版本与办公布局变化仍需重新确认；不会自动续跑旧任务。
- 新需求支持按已应用组织的办公团队选择成员，不把办公团队与设计中心发布的团队模板混同。空团队、未分配成员及同层不同团队分别处理，不回退为全组织。
- 后端创建、预览、预检统一校验 `office_team_id` 与 `office_layout_ref`。冻结团队、部门、楼层、成员与版本来源，创建和布局应用共用锁以防陈旧确认竞态。
- 新建任务先做只读执行检查；不以“模型启用”代替主/备用模型、协议、工具和执行环境检查。检查通过仍不代表真实模型推理或项目交付已完成。
