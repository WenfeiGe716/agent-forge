## 已实现范围

- 新任务唯一模式为团队自治；用户不选固定流程、编排图、讨论轮次或固定开发角色组合。
- 支持单人；多人负责人来自明确选择或冻结授权池内已配置的唯一汇报关系，不从组织中猜人。
- 负责人和成员可通过 `inspect_team` 查看同一冻结团队的职责、Skill、实际可用工具及当前工作。输出不包含 API Key、供应商凭据或其他运行内容。
- 负责人 `assign_work`，成员 `send_message(request_reply=true)` 发起具体求助；请求创建新的工作分配，真实结果唤醒请求者。通知不强制回复。已完成步骤不自动重放。
- `read_work_result` 可读取同任务已集成的成员成果，返回当前集成提交和 SHA-256，不覆盖个人草稿。读取受成员原有权限和文件额度约束；已读成果变更后必须重新核验才能引用交付。
- 负责人按需要召集/结束多人讨论，不再全员固定轮流发言；单人不建会议。当前实体场地仍复用已有会议室/工位远程回退，休息区讨论调度未在本版本增加。
- 成员可按已授权工具处理文档或代码；自主任务接通现有工具发现、Skill 脚本、安装申请和精确命令审批，不新增操作系统权限。
- 成员阻塞先回报负责人，负责人可调整做法；暂停、取消、预算耗尽、持续无可执行工作不算完成。
- 负责人提交真实文件/工作证据或完整文字成果，并经过无未完成工作、未决审批和活动会议的检查后生成交付候选。最终验收仍需用户明确接受该摘要。
- 固定项目检查仅在单次创建时显式选择；默认不会给文档任务强加项目测试。未执行的测试和独立审查明确标为未请求，不伪造通过。
