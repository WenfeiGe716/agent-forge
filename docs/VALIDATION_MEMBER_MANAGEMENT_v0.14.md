# 模型批量管理与成员配置验收 · 2026-09-10

本次范围：按供应商批量启停、直接选角色模板创建成员、Skill 独立绑定、明显的楼层入口、部门和团队筛选，以及模型配置保存。没有使用真实供应商推理，也不把配置保存当成业务任务已经执行成功。

## 使用入口

- 供应商与模型 → 选择供应商 → 批量启停。支持逐项选择和全选当前筛选；影响预览后明确确认。全量同步替换仍是独立操作。
- 添加 Agent → 从角色模板库选择。仅复制职责与来源版本，随后独立编辑、保存；现有模型、权限、部门与 Skill 不随角色模板自动改变。
- 成员配置 → Skill 独立绑定。可搜索已导入方法，选择已审核版本、个人参数、加载方式和局部启停；共享正文只读。修改正文需要在能力库建立并审核新版本。
- 楼层与部门 → 新增楼层／部门。默认打开当前已应用布局的可编辑副本；若已有未发布草稿则保留并继续编辑。新楼层包含必需公共配套，不复制员工。保存、发布、应用依然分离。
- 团队与成员 → 按部门、办公团队、启停状态或姓名岗位搜索；包含未分配部门和未分配团队。

## 定位与修复

真实表单回归先复现：只切供应商会清空候选模型，旧界面仍允许提交 null，造成原绑定被解除。完整选择供应商和模型的 API 保存原本正常。

现在完整表单和工作台快捷入口都阻止未完成的供应商选择。解除模型绑定需明确选择“暂不绑定”。不兼容的参数会指出具体模型和字段，可明确重置，不静默清空参数或备用模型。新运行冻结新配置，旧运行不改写。

部门采用 Agent 当前业务归属，不再被旧工位的部门遮盖。现有办公团队和位置仍来自明确应用的布局；不匹配时标记“空间待调整”，不擅自迁移工位或改写发布版本。
