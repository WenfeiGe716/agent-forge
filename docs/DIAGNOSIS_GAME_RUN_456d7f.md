## 排名假设与验证结果

在检查调度实现前已向主线程提供：

1. **后续激活在前序交付前准备，导致过期基线重复新增**：预测后续补丁可应用其原基线，只需先放入前序文档即失败。真实复放确认。

## 为什么出现权限提示与测试错误

运行创建时冻结的是 `local + ask`；当前项目配置已是 `local + full`。之后修改设计配置不会改变该旧运行的冻结权限，不能据当前卡片判断旧运行已拥有完全访问。

- 684 / 692：模型把 `.`、`tests`、`tag_normalizer.py` 相对工作区路径填入额外权限 `paths`。此字段只接受额外外部精确文件，故被拒绝。
- 695 / 705：模型重试为完整任务副本路径；它们位于平台受保护的数据树，仍被拒绝。
- 700 / 709：改为 `paths: []` 后正常生成申请，714 / 763 记录用户批准。
- 722：Nova 真实测试 9/9 通过。
- 787：Echo 前序副本尚未包含 Nova 实现，仍为 `NotImplementedError` 占位函数，真实测试失败。它如实记录失败，没有伪造。
- 940：Echo 后续副本包含实现，真实测试 9/9 通过；但随后在集成文档时因重复新增停止。

本次没有 `run_command` 被拒后才申请许可的记录。负责人在委派时要求先按权限流程申请，成员过度使用了额外授权入口。应明确“工作区内无需额外路径，普通受限本机命令先用已有 run_command；确有越界/联网需要才申请”，并给结构化纠错提示。**不应放开受保护目录或把 ask 改成 full 来隐藏问题。**

## 建议修复与回归边界

1. 同一成员的已经准备/启动但尚未集成的激活应优先、独占该成员；等待审批仍占用，答复后恢复原激活。后续新激活保持排队，前序集成后才创建副本。
2. 在准备副本前执行并发预算裁剪；不要只在实际推进模型前裁剪。
3. 保留 Git 原始拒绝的结构化、限长、脱敏信息：失败工作/成员、冲突文件、任务基线、集成版本。界面明确为“成果合并停止”，不显示“等待审批”；保留真实 patch。
4. 目标与项目约束冲突要暂停澄清，不自动改旧约束、不自动按旧 README 改写新任务。
5. 工具说明明确已有工作区授权与额外路径的区别。错误应告诉 Agent 如何纠正参数，而不是只报平台目录禁止。
6. 正确回归 seam：真实 `autonomy_tick + SQLite Task/Step + 工作副本 + Git 集成`。种入“已有成员 waiting_decision、来自已集成负责人的新消息工作、随后审批答复”的情况，断言先恢复旧工作，新工作无 base_commit；旧文件集成后才准备新工作，后续文档补丁应为修改而非重复新增。另测 `max_parallel=1` 不提前准备第二位成员，且真实同文件冲突仍拒绝。
