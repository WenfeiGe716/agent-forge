# Agent Forge v0.8.1 — 登录首页与多供应商管理

日期：2026-09-09。基于已交付v0.8.0源码修改。此次只调整平台入口、供应商管理和成员模型选择，不更换任务编排或3D行为内核。

## 1. 修正的问题

v0.8已有账号登录，但管理员登录后，若`/setup/status`返回`needs_connection`，`App.tsx`会自动替换整个工作台为供应商接入向导。这把“模型是否可执行”错误地变成了进入工作台的条件。

v0.8.1的默认入口仅取决于账号认证：

- 未登录／退出／会话失效：平台登录页。
- 已登录：办公室／工作台；零供应商、零模型、所有供应商停用都不会触发配置跳转。
- 配置入口：独立“供应商与模型”页面；管理员显式点击后才打开新增或可选测试弹窗。
- 实际任务：按参与成员检查模型、供应商、工具能力、外发与其他权限。不把未参与且未配置的Agent当成全局阻塞。

`needs_connection`仍是兼容的状态查询字段，不再决定前端路由。有效登录会话允许恢复办公室；登出时清空客户端成员、项目、任务、模型、对话和管理弹窗状态。办公室顶部新增实际退出登录按钮，账号头像由登录用户生成，不再固定为“A”。

## 2. 多供应商与Agent独立配置

### 两种新增操作的边界

| 入口 | 行为 |
|---|---|
| 添加供应商 | 调用现有`POST /api/providers`，只保存独立连接。不调用模型、不创建默认型号、不绑定成员。 |
| 添加模型 | 选择供应商后调用`POST /api/models`。同一家可有多个模型。 |
| 连接并测试 | 可选弹窗，主动发起两次真实HTTP工具往返，通过后保存该连接与一个明确选择的模型。 |

供应商列表同时展示协议、地址、启停、下属模型数量和当前使用成员数量。模型支持供应商筛选，并显示对应使用成员。添加第二家不会覆盖第一家；不设置全局唯一供应商。

Agent编辑器增加明确的“模型供应商”选择，与“独立模型绑定”联动。切换供应商时清空未保存的型号选择，不自动选择目录第一项。保存仅影响当前成员；取消不写入。已有备用模型和参数仍可独立配置。

快捷连接接口新增`bind_unassigned_agents`，默认`false`；`install_builtin_skills`默认改为`false`。两者均须明确勾选才执行。批量绑定只填补未绑定且启用的成员，保留已有模型、运行参数和非空Skill。

**接口兼容注意：** 以前直接调用`/api/setup/connect`并依赖其隐式初始化行为的客户端，现在须显式提交上述选项。数据库中的旧绑定不受影响；没有新增数据库表或修改历史任务快照。

### 联合验收经过

1. `bash start.sh --port 8797 --no-auto-sandbox`启动真实本地API、数据库与运行器。未登录接口返回401；首页显示登录页，没有API Key字段。
2. 错误密码留在登录页；正确密码直接进入四名未绑定角色的办公室。此时供应商、模型、项目和运行列表为空。
3. 有效会话重新加载仍进入办公室。用户主动进入供应商管理；新增弹窗可取消，不控制登录或主页。
4. 从实际管理页保存两个不同协议的供应商连接；没有发生模型请求。创建三个模型，其中两个归属于同一家供应商。
5. 实际操作模型筛选，并在成员编辑器分别绑定Atlas→模型A、Nova→供应商B的模型、Echo→模型A2；Sage保持未配置，不阻塞管理。
6. 主动打开可选连接测试，检查错误JSON不发请求、模型目录不自动选型号；实际HTTP脚本服务完成两次工具往返，保存第三个连接。默认不改变任何现有Agent或Skill。
7. 所有供应商停用后仍能退出并重新登录办公室；只读账号同样登录后可读管理列表，但不可新增连接。
8. 实际停止并重启服务：供应商、独立绑定、登录会话和加密密钥保留，工作台仍不跳转接入向导。
9. 760px下管理页与登录页没有文档水平溢出；正式静态目录仍无旧预览入口和演示控制。

后端新增检查还核对：未参与的未配置Agent不阻塞配置快照；选中的成员未绑定则明确返回该成员名称；跨供应商的实际运行快照保留两个独立凭据版本。

### 测试中修正

原有供应商和模型表单的select隐式可访问名称混入option文本。补充了稳定的显式`aria-label`后，重新执行完整浏览器流程通过。供应商管理新增卡片和可选弹窗采用现有深色配色，避免深底深字。

## 5. 复验

```bash
bash scripts/install-offline.sh
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
node tests/visual/behavior.test.mjs
node tests/visual/etiquette.test.mjs
node tests/visual/meetings.test.mjs
node tests/visual/city.test.mjs
```

浏览器专项为`tests/e2e/v081_login_providers_acceptance.py`，需系统Playwright、Chromium及Xvfb。在未初始化`.local`的独立源码副本上运行；脚本拒绝覆盖已有部署，使用8797/8098两个本地测试端口。

旧版本的安装／升级管理规则仍见`ADMIN_v0.8.md`，不渲染在登录页或办公室。此修改不承诺在途工作流热升级。
