## 为什么现在可以离线安装

没有修改系统DNS、代理、TLS验证或浏览器管理策略。公网依赖源仍无法解析。本版提供一条不依赖公网包仓库的执行路径：

1. 前端随包携带有许可证及来源哈希的React 18.2运行时、TypeScript 5.8.3编译器，构建为本地单文件页面。没有伪造npm锁文件，也不假装安装了原版Three.js/ReactFlow。
2. 当前验证前端使用**原生WebGL办公室、原生SVG任务图和内置SVG图标**。原Three.js/ReactFlow实现保留在`docs/legacy/`作历史参考，不是本轮验证对象。
3. `offline/wheelhouse/`是从本环境已安装发行包重新打包的27个wheel，**不是从上游新下载的原始wheel文件**。原许可证和包元数据保留；使用新生成的SHA256锁定。来源见`offline/MANIFEST.json`及每个wheel内的`FORGE_REPACK_PROVENANCE.json`。
4. 新增**单进程本地持久化编排模式**，使用SQLite和活动日志，和Temporal适配器共享任务流程规则。安装时只能选择一个编排器，不会双重执行。本轮联调使用本地模式；它不是Temporal的分布式高可用替代品。

## 路径A：安装并启动实际平台

离线包适用 **Linux x86_64、CPython 3.13、兼容wheel标记的系统库**。需要Git；修改前端并重建时需要Node（本轮使用22.16.0）。Python、Git、Node、Docker、浏览器和模型权重本身不包含在包里。ARM/macOS/Windows或其他Python版本不能强装这些wheel。

在源码根目录：

```bash
bash scripts/install-offline.sh
.venv/bin/python scripts/start-local.py
```

默认地址：`http://127.0.0.1:8787`，账号`admin`。随机密码及加密密钥在`.local/config.json`，首次生成后不会覆盖。不要提交或转发这个文件；丢失加密密钥将无法解密供应商凭据。

可换端口：

```bash
.venv/bin/python scripts/start-local.py --port 8791
```

修改既有部署端口或通过其他域名访问时，需同步修改`.local/config.json`中的`ALLOWED_ORIGINS`。默认只监听回环地址。团队局域网访问应配置HTTPS反向代理和安全Cookie，不要将未加TLS的登录服务暴露到公网。

启动后的配置顺序：添加供应商连接 → 添加模型 → 给各Agent绑定模型 → 导入本地项目 → 配置执行环境和验收命令 → 创建需求 → 审批计划 → 检查产物并验收。

**真实平台不会启动脚本化模型，也不会启用宿主机任意命令执行。** 需要运行构建/测试时，必须连接实际Docker/gVisor沙箱broker。未配置模型、缺少broker或工具链时会明确失败/转人工，不降级为模拟通过。本地模式的broker需要使用与API一致的工作目录映射和`SANDBOX_TOKEN`。

现有Docker/Temporal部署路径仍保留：`scripts/init.sh`、`scripts/start.sh`。它需要对应镜像、Docker、runsc、网络/内部依赖源；**本轮未执行该路径的镜像构建和整栈验收**。不要同时让本地与Temporal运行器管理同一个数据库/数据目录。

## 路径B：立即复现本轮协作验证

此路径不需要真实模型密钥，也不需要Docker，因为使用了**严格受限、明显标识的验证夹具**。它仅证明平台流程和交互，不证明任意项目执行环境或模型开发质量。

```bash
bash scripts/install-offline.sh
bash scripts/start-validation.sh
```

默认浏览器地址`http://127.0.0.1:8787`。验证数据和随机登录凭据保存到`/tmp/agent-forge-e2e/`，密码见其中`environment.json`。日志和数据不是正式工作区，不会导入你的真实代码。目录已有数据时默认拒绝覆盖，需显式`--reuse`或指定新的`FORGE_E2E_STATE`。

脚本会创建两种协议连接、四个角色和一个独立示例项目。登录后创建任务：

> 修复add函数的加法错误，整理验收说明，补充负数和零值测试。

批准计划后，可以观察并行开发、消息发送、下游读取消息、成果集成、自动测试和审查。最后由你点击验收。页面始终显示黄色“验证环境”提示。

验证命令服务不是沙箱替代品：它只接受一条固定unittest命令，只允许白名单中的精确源码字节，并把已核验内容复制到新的临时目录执行。任何其他命令或源代码都会拒绝。**不要将它连接真实模型或改为允许任意代码执行。**

## 功能细节与边界

| 能力 | v0.2行为 |
|---|---|
| 多供应商 | OpenAI Chat Completions兼容协议、Anthropic Messages协议；支持多个独立连接，非“原生支持所有厂商接口” |
| 独立Agent配置 | 每个Agent单独选择模型、备用模型、指令、模型参数、执行参数 |
| 参数继承 | 平台→项目→角色→Agent→单次运行；部分总量参数只属于运行级；保存最终配置及来源 |
| 消息协作 | `send_message`只能发给本次运行参与者，有长度、总量限制和操作去重；下一轮加入接收者上下文，不绕过依赖或唤醒已结束任务 |
| 任务交接 | 依赖完成后生成可追溯交接事件；下游工作区从集成代码创建，并获取上游摘要 |
| 本地持久化 | 已完成活动记录可复用；留下started的未知操作禁止自动重放，保留现场转人工；单进程锁，不支持多副本HA |
| 执行时间预算 | 本地模式保守累计活动耗时，排除人工等待和停机时间；并发活动耗时相加，不等同于墙钟耗时。Agent自身时间按已持久化轮次累计 |
| 3D办公室 | 点击模型/标签、拖拽旋转、滚轮与键盘缩放、复位、聚焦、日夜、工位/会议布局、8人分页 |
| 3D与实际协作 | 任务状态与真实消息/交接事件驱动标签和连线。手动切换会议布局不等于发生真实会议，界面明确提示 |
| GLB | 会话内静态模型预览及恢复；仅内嵌、未压缩三角网格、不透明基础色，≤3MB/5万面；不支持纹理、骨骼、动画、外部资源或持久化模型配置 |
| 任务图 | 查看依赖、缩放、平移、打开任务契约与交付结果；不是可随意修改运行中DAG的编辑器 |
| 人工控制 | 批准/拒绝、暂停/继续、取消、成果验收；审批绑定摘要，暂停/取消在执行边界生效 |
| 成果 | Git补丁、源码ZIP、测试审查报告；原项目不被直接修改，不自动推送/合并/生产发布 |

### 可配置上限

`max_agent_messages`是本轮新增运行级字段（0可禁用发送，默认200）。其他上限包括`max_model_calls`、`max_steps`、`max_parallel`、`max_tasks`、各类超时及沙箱资源。设置界面可以修改默认值，已有运行继续使用创建时快照。

本地运行器安装级`MAX_ACTIVE_RUNS`默认2，`MAX_ACTIVE_ACTIVITIES`默认4，在`.local/config.json`中配置，重启生效。消息不是无限自由讨论；规则与验收仍由平台控制。金额硬预算、Token硬上限和供应商速率分桶尚未实现，不能用调用次数限制冒充这些能力。

## 开发与验证命令

```bash
# 无公网也可以重新生成前端
cd frontend
npm ci --offline --ignore-scripts --no-audit --no-fund
npm run build
npm run check
cd ..

# 真正执行后端自动测试
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q

# 环境诊断（只读；不修改DNS、代理或TLS）
.venv/bin/python scripts/check-dependencies.py
```

前端构建使用TypeScript转译与语法诊断，**不是完整语义类型检查**；本轮另做了实际浏览器交互测试。浏览器自动测试在`tests/e2e/browser_acceptance.py`，需要另行准备Playwright、Chromium和可用图形环境，离线包不包含这些浏览器工具。

本次执行容器的浏览器管理策略禁止全部URL导航。没有禁用该策略：以`page.set_content`加载本地构建产物，再通过受限测试转接把`/api`请求和实际HTTP SSE送至本地后端。实际DOM/WebGL和后端联动已测试；普通URL导航、跨域/Cookie部署策略、原生EventSource自动重连和浏览器下载对话框仍须在目标环境复核。后端SSE的Last-Event-ID续传已单独通过真实HTTP测试。

## 安全与升级

不要带未结束任务直接从v0.1替换编排实现。先停止创建任务、处理在途任务、备份数据库/工作目录和加密密钥，再在独立目录验证。本地v0.2默认使用新的`.local/`数据库，不自动改写旧部署的数据。

程序启动会创建新增表，但没有完整数据库版本迁移体系；生产数据库升级、备份恢复、长期运行、压力测试、沙箱逃逸审计、供应链审计仍未完成。完整生产化缺口见`docs/VERIFICATION_v0.2.md`，历史设计文件不代表全部功能都已验收。
