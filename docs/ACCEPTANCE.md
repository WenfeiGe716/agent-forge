# 目标主机集成验收清单

本清单是尚待实际执行的验收步骤，不是已经通过的报告。

| 检查 | 方法 | 通过标准 |
|---|---|---|
| 前端构建 | npm install后npm run build，保存锁文件 | TypeScript完整检查与Vite构建通过 |
| 基础服务 | start.sh后看compose ps和worker日志 | API、数据库、Temporal、Worker、broker均正常；非只看web首页 |
| 沙箱隔离 | 执行可信固定测试命令；探测网络/挂载/权限 | runsc确实运行、无网络、无Docker socket、工作区外不可写 |
| 模型连接 | 分别测试一个OpenAI兼容和一个Anthropic模型 | 主调用、工具调用、工具结果、备用切换与参数约束符合预期 |
| 多供应商协作 | 负责人和开发/审查分绑供应商，运行tiny-project | 真实请求各自发出；7次是测试桩用例，不是固定真实调用次数 |
| 审批边界 | 拒绝/批准计划，发送错误摘要；验收旧成果 | 未批准不修改代码；错误或旧摘要不生效 |
| 成果 | 下载patch/report/source，核对原目录 | 修复正确，测试真实运行，原目录未改，报告可追溯 |
| 实时视图 | 断网重连、刷新、多页面查看 | 事件补齐，3D/任务图/日志与同一真实状态一致 |
| 权限 | admin/developer/viewer及非项目成员访问 | 跨项目读取与写操作被拒绝，停用后会话失效 |
| 人工控制 | 执行中暂停、继续、取消 | 请求与已生效状态区分，等待在途调用边界，记录明确 |
| 故障与重复 | 停Worker、返回429/超时、重复提交 | 不丢持久化意图，不盲目重做未知外部操作，转人工可定位 |
| 冲突 | 两任务并改同一行 | 保留两份工作区与补丁，不能静默覆盖 |
| 配置快照 | 开始运行后改默认值/禁用供应商 | 普通配置冻结；安全撤销下一调用生效 |
| 备份恢复 | 新建干净测试环境恢复停机备份与密钥 | 用户、配置、任务、成果可读且凭据能解密 |
| 业务基准 | 代表性功能/修复/补测试任务，对比单Agent | 记录成功率、质量、成本、耗时、人工介入，按数据决定成熟门槛 |

不建议在本清单通过前接入生产部署工具。没有测试命令的项目可以参与开发，但不能把“模型认为正确”标成“测试通过”。
