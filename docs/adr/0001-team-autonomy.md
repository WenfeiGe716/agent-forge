# 团队自治是新任务的唯一创建模式

用户确认目标、团队范围及执行权限后，由负责人动态分工、成员定向沟通，按真实成果提出交付候选；用户不再选择固定编排模板、发言顺序或讨论轮数。组织与能力配置依然由人治理，团队成员可以查阅本次冻结的能力目录，但不能转移他人的权限。

后台仍保留持久任务调度、消息身份、单成员激活、并发预算、审批与证据校验。求助会创建新的工作分配而非重放已完成任务；交付候选与最终人工验收是不同状态。文件成果先集成再交接，使下一次分配看到已确认的工作副本；后台调度不等待 3D 行走。旧固定流程代码暂作为内部回归参考保留，不再通过新建任务 Interface 提供，已获用户授权的旧运行记录单独备份清理。

固定项目检查改为逐次显式选用。未执行检查不视为通过，文档与分析任务不强制套用开发流程；用户的最终验收仍绑定具体交付摘要。

正在工作的成员不会被后台覆盖个人工作副本。`read_work_result` 在既有文件读取权限和成员读取额度内，读取本次已集成工作声明的成果，返回当前集成版本与内容摘要。引用已读取但后来被其他成员改写的成果时，负责人必须重新读取后才能提交；这与修改自身文件、最终人工验收分别处理。
