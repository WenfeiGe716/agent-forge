# Agent Forge v0.5.0 — 坐姿接待、管理工作台与多轮编排

交付日期：2026-09-09。对象：团队内部、本地部署的软件开发协作平台。

## 结论

本轮已修改默认人物的座椅接触与站坐姿态，加入可追溯的来访接待，接通任务看板、项目、模型、成员管理及可执行多轮编排。源码、构建产物、离线依赖、自动测试和本轮实际浏览器证据随包提供。

实际联调使用本地持久化编排、SQLite、真实HTTP双协议测试服务、真实Git以及固定可信unittest。模型响应仍为明确标识的脚本化夹具，不是真实LLM；本轮不宣称Docker/gVisor、Temporal/PostgreSQL、任意项目开发质量或生产安全已经验收。

## 1. 工位坐姿和来访

### 几何与姿态

工位待命、思考、读代码、打字、审查、等待、暂停及看手机均采用坐姿。骨盆底部贴合座面（场景单位0.715），大腿前伸、小腿向下、脚贴近地面；坐姿头部比站姿降低约0.295。起身和坐下有480毫秒插值。起身接待时身体平移到椅子旁，不在座面上伸直双腿。

默认程序化人物支持这些姿态。外部静态GLB仍不能凭空获得骨骼和坐姿动作，导入时明确提示；可恢复默认人物体验姿态。

### 确定性接待规则

| 情况 | 行为 |
|---|---|
| 工位无来访 | 坐着办公或待命 |
| 同事来访 | 按成员的 `peer_reception` 坐着沟通或起身沟通 |
| 领导来访 | 必须起身，覆盖“同事来访坐着”偏好 |
| 来访结束 | 来访者回工位，接待者重新入座 |
| 同时有多人来访 | 参与者互斥，后续来访有界排队；过期事件不反复播放 |
| 运行切换、结束、暂停异常或失联 | 停止不再匹配的来访演绎，不虚构持续沟通 |

领导按 `reports_to` 直属关系及上级链识别；未设置直属领导时，默认把负责人角色视为领导。成员管理可修改直属领导和同事接待偏好；API拒绝自己向自己汇报、不存在的上级及循环汇报关系。这些关系只控制场景礼仪，不增加工具权限。

只有新鲜的实际消息、委派、成果交接或讨论上下文交接事件才能发起来访。相同事件去重，同一参与者一次只参加一个来访。人物寻路到接待工位侧边；详情显示事件号及行为原因。

行走和起身是实际通信的空间表达，后台消息交付与任务执行不等待人物到达。空闲生活继续使用v0.4状态机：无全局任务且来源新鲜时才允许喝水、手机、沙发、卫生间和伸展；有任务立即抢占。

## 2. 管理页面与真实接口

| 页面 | 本轮可操作内容 |
|---|---|
| 任务看板 | 待启动、执行中、等待确认、暂停/异常、完成/取消五列；按项目、状态和名称/需求搜索；点击卡片进入任务图、控制、审批、逐轮记录与产物 |
| 项目 | 导入本地项目副本、编辑项目规范、镜像、测试命令、外发授权、成员权限、运行参数；归档后不能创建新运行 |
| 模型与供应商 | 多连接、多模型、地址/协议/凭据、模型参数、启停、连通性测试；新增的模型停用规则在创建运行时校验 |
| Agent团队 | 创建和编辑角色、独立模型/备用模型、指令与参数、直属领导、同事接待方式、启停 |
| 多Agent编排 | 创建、编辑、启停模板；选择少数成员、排序、轮数、串行或并行、停止条件；直接使用模板创建任务 |

正式页面均请求真实API并持久化，不是单独演示管理按钮。项目、供应商、模型和成员的原有写接口继续使用；模板新增 `/api/orchestrations` 与 `/api/orchestrations/{id}`。模板带版本，更新采用数据库条件更新防止覆盖已变化版本；运行绑定不可变模板快照，旧版本启动请求返回409。

看板当前显示接口返回的最近100条可见运行，并明确显示条数，不宣称全历史分页。状态由编排器更新，不允许把卡片随意拖成“已完成”来绕过验收。项目归档及模型/成员停用保留历史；没有物理删除历史记录的向导。

## 3. 可执行编排

### 两种流程

1. **仅多轮讨论**：只调用所选成员，不要求一位负责人/一位审查等固定角色；讨论只读项目，可以读取文件、发送运行内消息并提交发言。最终生成纪要和JSON，等待人工接受。
2. **讨论后软件开发**：指定子团队先讨论，结果传入负责人规划；此后保留原有计划批准、开发、Git集成、测试、独立审查、有限返工、成果验收流程。完整开发团队仍需符合原有职责要求。

### 参数与上下文

`participants` 指定参与者与顺序；`rounds` 为最多1–12轮；`strategy` 为串行或并行；`stop_when` 选择固定轮数或全体明确 `ready` 后提前结束；`min_rounds` 约束最少轮次；`prompt` 描述讨论目标。

- 串行：A→B→下一轮A→B。每次发言读取此前全部已完成发言，包括同轮前序成员。
- 并行：同轮成员仅读取上一轮及更早的结果，整轮完成后进入下一轮。即时协作消息同样受轮次边界约束，不会因为某个成员执行较快而泄露到同轮较慢成员的输入。留待后续的消息保持排队，不伪称已送达。
- 所有成员明确 `ready=true` 且达到最少轮次时才提前停止。这个标记是模型提交的状态，不等于客观正确性或业务验收通过。

例如两名成员、3轮：串行的先前发言数量是0、1、2、3、4、5；并行是0、0、2、2、4、4。本轮测试实际检查了每一次输入。

每次发言有独立任务记录：成员、轮号、顺序、输入发言键、实际模型结果与状态。工具白名单在服务端执行，讨论阶段不能写文件或运行命令。原有模型调用预算、执行步数、上下文上限、暂停/取消、安全授权和未知活动保护仍生效。

讨论成果为 `discussion.md`、`discussion.json`、`report.json`，不会伪造代码补丁或测试通过。纯讨论的自动验证状态为“未执行代码验证”，人工接受时必须写意见。开发模式才按实际执行生成Git补丁、源码ZIP及测试/审查报告。

当前编辑器是上述有界流程的参数化可视化编排，不是任意分支、嵌套循环、多组讨论串联的通用流程语言；不能任意修改已经运行的DAG。讨论当前每轮保留独立工作副本，较大仓库、多成员、多轮次的磁盘/性能需要单独评估。

### 实际HTTP链路

已实测：双成员串行3轮、并行3轮、至少2轮后一致就绪提前结束、单次调用预算停止、暂停期间调用不增加、继续后取消、模板快照隔离与过期版本拒绝，以及讨论后完整开发。

“讨论后完整开发”实际发生4次讨论调用及原开发流程16次调用，共20次HTTP模型请求，生成真实Git修改，运行加法/负数/零值3项固定单测，通过独立脚本化审查，最后人工验收。原始目录未被修改。代码与测试执行是真实的；发言、计划和审查决定由明确的脚本化服务提供，不能推导真实LLM有相同能力。

浏览器实际创建另一份两成员3轮模板并启动任务，检查6条持久化发言、最后一条输入的5份先前发言、正确的纪要链接，再通过界面完成真实人工验收。项目规范、模型参数、成员领导/接待偏好也经浏览器保存至数据库。

### 实测中修正

修正管理页浅底卡片继承浅色文字导致的对比度问题；纯讨论详情不再展示不存在的源码ZIP和补丁；验收说明区分只读讨论与代码测试；新增并行消息屏障，避免同轮时序污染。测试脚本也修正了会匹配所有示例需求的搜索词，以及与真实按钮文本不符的选择器。最终结果对应当前交付产物。

## 5. 三种运行边界

- **正常平台**：`start-local.py` 启动真实API、本地编排与持久化，初始不添加虚构模型或模板。需要自行配置模型服务；开发构建/命令还需真实沙箱broker。
- **HTTP验证环境**：`start-validation.sh` 使用隔离数据库和明确标记的双协议脚本服务；只执行固定、字节内容核验的可信unittest，不能拿它执行任意真实项目命令。
- **离线交互预览**：`workbench-preview.html` 使用同一App、看板和编辑器，但由单独的内存适配器提供示例数据。保存仅在本页生效，刷新重置；创建任务不执行模型或代码。顶部始终有“离线界面示例”标识。“同事来访/领导来访”只注入示例事件。

## 6. 环境与未验证范围

本轮环境为Linux x86_64、CPython3.13、Chromium/ANGLE SwiftShader软件GPU。离线wheel沿用此前从已安装发行包重新打包的27个包，保留许可证/来源/哈希，不是新下载的上游原始wheel。其他平台应使用受信任源安装对应版本，不能强装此包。

浏览器管理策略禁止URL导航。没有禁用该策略：使用 `page.set_content` 加载真实产物，正式页面通过受限桥接请求本地API及真实HTTP SSE。因此不覆盖普通地址栏导航、HTTPS/Cookie部署、浏览器原生EventSource断线恢复和下载管理器。产物另外以真实HTTP读取检查；目标部署主机仍需验收原生访问路径。

仍未验证：真实供应商/LLM开发质量、Docker/gVisor隔离安全、Temporal/PostgreSQL整栈、硬件GPU帧率、完整TypeScript语义检查、长期运行/压力/备份恢复/HA及供应链安全审计。前端本轮构建是转译+语法诊断+浏览器实测，不应称为完整tsc类型检查。

人物仍为程序化关节模型；不包含成熟角色资产系统、任意GLB骨骼绑定、完整动态人物避碰或跨客户端帧级同步。新接待行为保持静态家具寻路及参与者互斥，不把它等同于所有物理碰撞情形已验证。
