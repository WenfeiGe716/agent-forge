# v0.4 行为与交互验证报告

## 1. 本次实现

任务动作与空闲动作是两个有优先级的来源，二者不互相改写业务结果。界面和几何不使用网络CDN或外部美术资源。

### 执行中的动作

后端GET `/api/office/state`扫描所有未释放运行，计算每个Agent的全局占用。前端选中的运行只影响查看内容，不影响角色是否有事做。排队、依赖等待、计划审批、成果审批、暂停、异常均保留占用；任务完成或取消后重新确认空闲。

| 依据 | 工作显示 |
|---|---|
| 任务/模型活动状态 | 思考或规划 |
| read_file、list_files、search_files | 阅读代码 |
| write_file、apply_patch | 修改代码/打字 |
| run_command | 执行命令/查看屏幕，不把任意命令假称为测试成功 |
| review任务 | 审查 |
| send_message/agent.message/交接 | 只显示确有事件的通信、气泡和发送方/接收方连线 |
| 工具完成 | 回到等待下一步/思考；不自行宣布任务完成 |

动作记录保留来源、run_id、task_key、event_id和原因。私有项目对无访问权的人只暴露必要的“其他任务占用”，不返回私有任务ID、内容、事件或任务数。

### 空闲生活

只有后端完整、新鲜的占用快照明确说明空闲，才能启动场景行为。活动选择使用固定成员ID偏移及固定循环顺序，不调用随机数或模型。

| 动作 | 过程及设施 |
|---|---|
| 喝水 | 占用饮水机槽位→寻路→举杯喝水→返回；容量2 |
| 看手机/摸鱼 | 在个人工位使用手机；任务到来即撤掉手机姿态 |
| 沙发小憩/偷懒 | 占沙发位→走过去→闭眼小憩→返回；容量2 |
| 卫生间 | 占用门口→走到门→人物隐藏、显示使用中→返回；容量1，无室内私密画面 |
| 伸懒腰 | 在个人位置进行短时伸展，不占公共设施 |

空位不足时留在原工位排队，固定ID排序仲裁。默认空闲宽限35秒、最大错峰25秒、结束后的冷却30秒。默认时长：喝水9秒、手机13秒、卫生间14秒、小憩16秒、伸展7秒；管理员可在“空闲策略”调整。动作时长从抵达设施后计时。

### 抢占、断线和消息

占用变为有任务时，在收到快照的同一状态机处理过程中结束空闲、释放槽位、清除杯子/手机/小憩姿态，卫生间中的人物重新可见并回工位。网络传输仍有延迟；本地动画不是零网络延迟保证。后台执行不会等待行走完成。

来源异常、缺失、分页未齐或超过5秒没有新鲜确认时，进入安全等待，不用空闲动画掩盖失联。恢复后重读快照。重复事件不重复播报；旧消息仍可看历史，但不被重新渲染成此刻新发生的对话。短时气泡具有事件ID，可追溯文本。

空闲日志在前端独立存储，有上限，不计作业务工具调用、模型会话或任务成果。任务的状态机、权限、预算和验收仍由后端管理。

模型响应来自明确标识的双协议HTTP测试夹具，不是真实LLM。固定测试服务不是任意代码沙箱。不能据此宣称真实模型的自主开发质量、Docker/gVisor安全或多Agent相对单Agent收益已验证。

## 3. 三种数据边界

- **真实平台：** 显示数据库的实际成员（本轮4位），占用与消息来自实际API，默认不添加假模型或假任务。
- **独立预览：** `office-preview.html`的14人是明显标识的示例输入，按钮改变示例状态，不访问API或执行代码；空闲宽限缩短便于观察。
- **场景演绎：** 喝水、手机等是角色表现，不代表Agent真的拥有生理需求或浪费模型资源；不会给真实任务添加虚构“会议/休息”执行记录。

## 4. 环境与尚未完成

浏览器为Chromium/ANGLE SwiftShader软件GPU，视口1600×1000及1100×850，实际帧率约4–5fps。没有硬件GPU帧率验收。录屏保留源帧时间间隔；视频编码20fps会重复帧，不能当作渲染20fps证据。

测试容器禁止URL导航；未修改浏览器管理策略。使用`page.set_content`加载真实单文件产物，实际平台通过受限HTTP/SSE桥接连接真正的本地API。独立预览不使用API桥接。这验证DOM/WebGL/API联动，但普通地址栏导航、Cookie/HTTPS部署、浏览器原生SSE重连与下载仍需目标环境验证。

其余边界：

- 程序化关节人物和基础光照，不是高质量美术资产、完整PBR或复杂骨骼动画系统。导入GLB仍是受限静态会话预览。
- 网格寻路绕静态家具，设施容量已控制，但尚无完整的人物间动态避碰；不把70条可达测试等同于所有实时碰撞情况验证。
- 空闲循环由各浏览器的新鲜确认和本地单调时钟驱动；无跨终端空闲帧级同步或持久化回放协议。客户端不同打开时间可能处于不同空闲阶段，业务占用必须一致。
- `needs_attention`保守保持占用，不因重试或换视图自动释放。原平台尚缺完整的“核验未知外部结果后关闭异常运行”处置向导；不能靠改画面状态解除风险。
- 全局占用查询面向本地小团队，尚未做大规模索引/投影缓存及压力测试。
- 本轮未验证真实LLM、Docker/gVisor、Temporal/PostgreSQL全栈、完整TypeScript语义检查、数据库升级/HA/长期运行/供应链审计。
