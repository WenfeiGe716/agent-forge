# v0.13.1 供应商目录与角色 / Skill 分离

日期：2026-09-10，Asia/Shanghai。原则：自动生成不自动生效；人拥有最终组织权。项目术语记录于根目录 `CONTEXT.md`。

## 供应商 → 模型目录 → 人工配置 → Agent 绑定

- 每个供应商连接按 `provider_id + revision_id` 独立缓存目录。同名型号不跨供应商合并；更换凭据、协议或地址后不借用旧连接缓存。
- 保存供应商自动读取目录；管理员打开供应商中心时，未同步或超过1小时的缓存会自动刷新一次，也可手动同步。只读用户读取现有缓存，不触发外部请求。
- 展示上游实际返回的全部型号，不因它是图像或嵌入模型而隐藏。不提供的能力、价格保持未知；目录可见不代表当前协议可调用，也不代表已经验证工具能力。
- 分别显示当前目录型号、已配置、配置已启用、目录中未找到。支持按连接搜索、未配置 / 已配置 / 未找到筛选。一个型号可以有多个人工参数配置。
- 同步失败保留当前连接修订最后一次成功目录及时间；旧请求或旧凭据的迟到响应不能覆盖新目录。上游移除的型号标记缺失，重新出现保留首次发现时间。同步不删除已配置模型、不启停、不改绑。
- 点“配置并启用”先打开人工表单，保存后才形成模型配置。工具能力默认未确认。主 / 备用绑定数量可见，启用或停用已有配置需明确确认。
- 编辑模型时切换供应商，会清空前一个连接的型号、名称、价格、上下文和工具能力确认，并加载新连接自己的候选列表；初次打开已有配置或指定候选不清空。

官方 OpenAI Responses / Chat、Anthropic Messages、DeepSeek 兼容协议、Gemini 原生接口和声明式自定义 JSON/HTTP 接入继续保留。官方服务快捷配置只填写协议与官方地址，型号由该账号的目录返回。ChatGPT / Claude Code 产品订阅、OAuth或CLI会话不等同于API凭据，未在本版新增这些登录方式。

原生目录支持有界分页：最多10页、2000个型号、单页8MB，超限报错并保留旧缓存，不把截断列表冒充完整目录。自定义JSON/HTTP目录仍按配置的一次响应解析，不承诺任意第三方分页或SDK协议。

参考 [OpenCodex](https://github.com/lidge-jun/opencodex) 的供应商专属模型目录、已选配置和缓存隔离设计；本平台不采用“空选择即全部启用”，也不改为全局单一供应商。

## 角色模板库：谁负责什么

- 独立目录、搜索、分类、来源、历史版本、原文与许可证查看。
- 新导入角色保存原始 `ROLE.md`；旧缓存读取 `references/original-agent.md`，不改写已有不可变修订，不用历史SKILL包装代替原文。
- 用户选择确切版本并确认成员名称和执行职责后，生成团队设计草稿；也可从现有团队编辑器添加角色，保留其他未保存修改。
- 名称、职责、模型、Skill、权限、通信、工位均可继续编辑。模型默认未绑定，Skill为空，仅保留提交和请求人工决定的最低工具集合，通信对象默认空；必须人工完善后发布。
- 每个成员保留 `item_id / revision_id / digest` 来源引用，后端校验所属条目与真实摘要。发布、实例化和任务快照保留引用；后续来源更新不会改写旧版本。
- 文档超过16000字符时明确标记节选，并保留完整原文及版本入口，不能静默截断。

生成草稿不安装Skill、不创建Agent、不发起模型调用、不批准或执行。停止或下架来源阻止新提案，但保留历史查看与已经发布的准确版本引用。

## Skill 商店：怎么完成工作

- 只列原生Skill，与角色模板分别统计；来源管理仍可统一维护GitHub / ZIP来源。
- 继续使用安装待审核版本、核对权限及工具、批准、绑定Agent、冻结版本、运行时加载的既有流程。
- 后端拦截角色模板通过旧商店接口安装、审核、绑定或再次发布为Skill，包括旧版曾重新发布而误标为Skill的角色来源。
- 不删除旧缓存、已安装历史或既有冻结任务；但旧角色Skill不能用于新的绑定与运行。用户需通过角色模板创建后续团队方案。
